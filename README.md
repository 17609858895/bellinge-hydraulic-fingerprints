# Bellinge dry–wet hydraulic fingerprints

Core analysis code for **Dry–wet hydraulic fingerprints distinguish sensor shifts from conveyance changes in urban drainage**. This repository contains the analysis implementation, environment specification and focused tests. It does not redistribute the DTU data, manuscript, figures or large fitted outputs.

## Data and environment

Use Python 3.12 and install `requirements.txt`. The recorded analysis environment used Python 3.12.3. Obtain the author-cleaned sensor CSVs from [DTU sensor data, version 2](https://doi.org/10.11583/DTU.12509249.v2) and the rain-gauge records from [DTU rainfall data, version 2](https://doi.org/10.11583/DTU.12509774.v2). Observe each dataset's license and citation requirements. Unpack the sensor directory containing `*_proc_v6.csv` and the rainfall directory `#3a_Raingauges` before running.

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python run_analysis.py --sensor-dir /path/to/2_cleaned_data --rain-dir /path/to/#3a_Raingauges
```

The final command prints the ordered plan. Add `--run` to execute it. On Windows, quote paths containing spaces or `#`. Outputs remain in this clone under `processed/`, `results/` and `results_corrected/`; inputs are read only. Logs are written under `logs/`. Full reconstruction and fitting require substantial memory and hours of computation. A fresh clone is recommended for a new analysis run.

## Analysis order

| Step | Main purpose |
| --- | --- |
| `panel` | Assemble the five-minute sensor panel from cleaned source CSVs. |
| `storage` | Reconstruct storage episodes and 10-minute landmarks. |
| `references` | Fit quarterly cross-fitted cross-sensor models and localize two-band changes. |
| `injections` | Compare dry–wet, raw-level and untyped residual representations. |
| `rain` | Assemble rain records and check their clock alignment. |
| `intervention` | Estimate rainfall-adjusted replacement responses, offset correction, event-definition and overlap sensitivities. |
| `warning` | Compare warning models, rainfall and anchor ablations, calibration, and delayed-feedback lower bounds. |

Select a subset with `--steps intervention,warning` after its upstream outputs exist. The runner uses dependency order regardless of the order supplied. Script 13 is explicitly passed `0` minutes, matching the retained unshifted rainfall clock. After script 08, its F04 reconstruction is copied to the frozen filename required by injection analysis; these two files were byte-identical in the retained study run.

## Interpretation and reproducibility

- The main diagnostic contribution is hydraulic-state conditioning and spatial interpretation of persistent residuals. Models, labels and parameter settings are retained from the analysis code; portability changes are recorded in `validation/code_provenance.json`.
- Script `03_extract_storage_events.py` reconstructs boundaries independently of a saved event list. It is a replacement implementation validated against all retained storage episodes. A separate local reconstruction refitted 104 storage-onset configurations and checked 300 reported quantities and 33,281 prediction rows. This is the validated scope of that fresh refit, not a claim that every branch in this repository was refitted during packaging.
- For close numerical reproduction, use the recorded package versions and thread settings. The validated storage refit used 32 threads for XGBoost AFT and 4 for LightGBM/logistic fits. Thread count and library versions can affect stochastic tree fits. The scripts preserve the original fitting defaults; configure the execution environment to match the intended run.
- `17_adaptive_feedback.py` is the current lower-bound analysis. It delays feedback until the relevant overflow arrival has been observed. Earlier onset-ordered adaptive scripts are intentionally excluded. Coverage concerns the defined retrospective overflow-labelled cohorts; it is not a guarantee over all future issued alarms.
- Historical candidate exceedance-integral outputs may be generated by the intervention scripts. The submitted inferential results exclude the F04 integral because an entirely missing outcome window could be assigned a zero sum. Use the documented peak and occurrence outcomes; an integral analysis would require an explicit coverage rule and re-estimation.
- `results_corrected/E17_conformal_leadtime.csv` and `E17b_alarm_physics_bound.csv` are the current adaptive outputs. Rain-onset windows can overlap; `22_overlap_uncertainty.py` supplies the intervention overlap sensitivity.

The manuscript and Supporting Information specify the scientific estimands, retrospective eligibility, working AFT labels, model settings, outcome windows and limits of inference. No raw data, private credentials, submission documents or institutional identifiers are bundled here.
